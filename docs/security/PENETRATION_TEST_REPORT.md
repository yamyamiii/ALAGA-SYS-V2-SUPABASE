# ALAGA-SYS Phase 13 penetration test report

Date: 2026-08-04

Scope: repository-level white-box review of the React client, routing/authentication, services, SQL migrations/RLS/RPCs, Storage policies, Edge Functions, AI boundary, notifications, documents/exports, and Backup & Restore. No hosted data was modified and no migration or function was deployed.

## Method and limits

The review combined static data-flow inspection, adversarial contract tests, migration hash verification, direct policy/RPC reasoning, dependency audit, and the existing Vitest suite. It is not a substitute for an externally authorized black-box test against the final production origin, hosted Auth settings, WAF, provider accounts, mobile devices, and real Supabase policy execution. Production database assertions below must be repeated after Migration 34 is applied in a controlled test project.

## Required post-deployment database probes

For each test identity, set its real JWT and issue REST/RPC calls through the public publishable key. Never use service role for a negative RLS test.

1. Query another resident's ID against `residents`, `households`, `appointments`, `health_encounters`, `vital_signs`, maternal/child tables, assistance notifications, and document RPCs. Expect zero rows or SQLSTATE 42501.
2. Suspend each role while its access token is still valid. Repeat reads and mutations. Expect only the self profile status read to remain.
3. Archive/unlink the resident record. `current_resident_id()` and `current_household_id()` must return null and own-data RPCs must fail closed.
4. Invoke all privileged functions as `anon` and `authenticated`; compare grants to the documented allowlist.
5. Attempt direct Storage list/download/upload/delete for both private buckets using every role.
6. Reuse idempotency keys with the same and different payloads, submit conflicting appointment slots concurrently, and retry backup/notification workers concurrently.

## Conclusion

The reviewed code has a strong least-privilege architecture and the discovered high-risk inactive-account paths have concrete forward-only fixes. The linked dry-run reports Migrations 32, 33, and 34 pending. Production approval is conditional on applying that reviewed sequence, redeploying affected Edge Functions, configuring hosted controls, running the negative-role probes, completing a restore drill, and accepting or remediating the scoped React Router advisory.
